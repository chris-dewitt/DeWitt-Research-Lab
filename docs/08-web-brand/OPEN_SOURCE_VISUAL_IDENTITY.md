# Open Source Visual Identity and Interface Language

## Design objective

The cream-on-black financial research terminal should make openness feel rigorous, archival, and alive. The visual system avoids both startup-gradient cliché and an undifferentiated wall of open-source logos.

## Primary visual language

- cream typography and fine rules on near-black;
- dense but readable tmux/workstation panels;
- document identifiers, revisions, checksums, and timestamps;
- restrained amber/green status signals only where semantic;
- architecture and lineage graphs drawn like research-terminal routes;
- model/runtime identity always visible in live traces;
- "OPEN RESEARCH" as a document status, never a fake government classification;
- paper/archive views for model cards, working papers, and evaluation reports.

## Open artifact card

Every card includes:

```text
ATTICUS CORE / MODEL / RELEASE CANDIDATE
Rights: Open-weight; derivative license pending exact base selection
Run: local / cloud
Modify: adapter + recipe + evaluation suite
Evidence: DRL-R3 / Forkability pending
Hardware: declared profile
Updated: timestamp
[RUN] [READ] [REPRODUCE] [FORK] [CONTRIBUTE]
```

Labels are generated from release metadata. The interface must not hard-code a higher maturity or openness class than the manifest supports.

## Open Stack lineage

The Open Stack view uses expandable routes:

```text
UPSTREAM PROJECT -> DRL ADAPTER/MODIFICATION -> LAB SYSTEM -> PUBLIC ARTIFACT
```

A node reveals license, exact revision, role, DRL owner, upstream link, security review, exit strategy, and DRL contributions. Visual prominence reflects architectural importance, not sponsorship.

## Contributor presence

Contributor credit appears in release timelines, model/data cards, research pages, and project histories. Opt-in contributor profiles can show roles such as evaluator, data steward, educator, accessibility reviewer, maintainer, or upstream contributor. The founder remains visible without erasing community work.

## Motion and terminal behavior

Motion explains flows: a model selects a tool, evidence reaches a claim, an evaluation gate passes, or a release lineage changes. Decorative scanlines, glitching, and fake typing are minimized. Accessibility settings disable motion, terminal effects, sound, and dense panel layouts.

## Homepage open identity sequence

Within the first viewport and first scroll:

1. laboratory name and public-interest mission;
2. open technology proof strip;
3. Atticus as operating intelligence and open model program;
4. live system map;
5. direct route to the Open Source portal;
6. actual release status, including honest "planned" or "experimental" labels.

## Anti-patterns

- model/provider logo mosaics without explanation;
- claiming "community" using fabricated activity;
- fake terminal commands that cannot be run;
- vague "open AI" badges;
- hidden license links;
- live metrics with no methodology;
- using Cold War aesthetics to imply government affiliation;
- sacrificing mobile readability for terminal density.
