# Website User Flows

## Faculty member or prospective adviser — primary

Wix Home -> current UNC-Chapel Hill degree and research direction -> Research ->
`TR-2026-001` -> methods/limitations -> source or recorded run -> About/contact.

No account, chat, or live backend is required. Success means the visitor can
state Christopher's current education, interests, selected work, and intended
computer-science direction.

## Research-oriented employer

Wix Home -> recorded run -> trace/architecture -> degraded behavior -> Projects
-> report -> About/contact.

## Research peer

Writing -> `TR-2026-001` -> method -> linked replay -> code/environment ->
citation or serious inquiry.

## Developer or tinkerer

Home -> replay -> Source -> local setup -> fixture run -> tests/artifact docs.

## Student or teacher

Writing/Methods -> integrated workflow lab -> replay transcript -> exercise ->
report and further reading.

## Future contributor — secondary

Open Source -> local run -> contribution guide -> architecture/spec -> good-first
issue -> pull request.

## Planned Atticus

Project page -> planned-state explanation -> replay/documentation fallback. A live
session route does not appear until deployment, identity, quota, consent, policy,
abuse, and cost gates pass.

## Failure and unavailable states

- replay widget fails -> static transcript, manifest, and source links;
- report renderer fails -> canonical repository document;
- external app is cold/unavailable -> recorded replay or documentation;
- artifact cannot verify -> explicit verification failure with no result upgrade;
- contact route is not approved -> no dead or placeholder submission form.
