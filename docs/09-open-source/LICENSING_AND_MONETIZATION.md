# Licensing, Trademark, and Monetization Strategy

## Recommended matrix

| Artifact | Default | Notes |
|---|---|---|
| Original software | Apache-2.0 | permissive, patent grant, commercial use |
| Documentation/teaching | CC BY 4.0 | attribution; code snippets separately Apache where marked |
| Original datasets | case-specific, often CDLA-Permissive 2.0 or CC BY 4.0 | source rights control |
| Model adapters/weights | upstream-compatible terms plus DRL notices | review each base |
| Website content/assets | marked per asset | brand assets not automatically open |
| DRL/Atticus names and logos | trademark policy | protects official identity |

## Monetization preserved

- managed Atticus/DRL hosting;
- consulting and architecture services;
- paid workshops and training;
- private deployment and integration;
- custom model/data adapters;
- enterprise support and SLAs;
- certification/verified plugin or benchmark services;
- commissioned research with disclosure;
- premium licensed datasets only where DRL owns rights;
- sponsorship without roadmap control.

Apache 2.0 does not stop others from commercializing forks. Differentiation comes from official releases, brand trust, data and evaluation quality, managed operations, expertise, and community.

## Contribution mechanism

Start with DCO signoff and inbound=outbound licensing. Revisit CLA before large contribution volume if relicensing/dual-license flexibility becomes strategically important. This is a legal decision gate, not an agent choice.

## Disclaimer

This is a project strategy, not legal advice. Formal releases and trademarks require professional review when stakes justify it.
